## ❗ 真实问题清单（按优先级）

### 1. 🧱 战斗系统架构不可复用
**现象**：剑士和弓箭手 80% 的代码完全重复（状态机、命令同步、索敌、追击 A-move 逻辑）。添加新兵种（枪兵、骑兵）得重写一遍。
**根因**：
- `UnitBase` 承担了太多职责（命令/战斗/索敌/分离/驻守图标），但没有提取出可组合的战斗组件
- 状态机在每个单位脚本内重复实现，没有统一的状态机框架
- `combat/` 目录是空的，没有任何模块化战斗逻辑
- 旧组件体系（`血量属性.gd` `步兵攻击.gd` `伤害框组件.gd`）已废弃但未清理

### 2. 🎯 索敌/攻击 AI 太简单
**现象**：当前是"找最近敌对目标"，没有智能权重（目标价值/威胁度/兵种克制）。
**用户反馈**：「不符合我的心意」
**待讨论方向**：目标优先级（低血量优先？高威胁优先？）、攻击切换策略、仇恨机制

### 3. 💀 死亡需要美术动画
**现象**：当前死亡是代码 Tween 效果（闪烁→缩放→淡出），不是 sprite-based 动画。
**需求**：用 AnimationPlayer 播放死亡动画（使用已有的精灵帧序列），建筑也应有摧毁动画而非简单的淡出。

### 4. ⚔️ 需要伤害类型 + 护甲类型
**现象**：所有伤害是裸数值减法，无克制/减免计算。
**需要**：
- 伤害类型：物理/魔法/真实/穿刺
- 护甲类型：轻甲/中甲/重甲/无甲
- 伤害计算公式：`最终伤害 = 攻击力 × (1 - 减伤率)`，减伤率由护甲类型 + 护甲值决定

### 5. 🏷️ 单位头顶血条/蓝条
**需求**：
- **不选中时**：单位和建筑不显示任何血条/蓝条
- **选中时**：
  - HP 条始终显示
  - MP/蓝条**仅当该单位有最大魔力值 > 0** 时才显示
  - 建筑不显示蓝条
- UI 表现跟随实际数值（当前生命值/最大生命值、当前魔力值/最大魔力值）

### 6. 🏰 防御塔无攻击逻辑
**现象**：`单位/建筑/防御塔.gd` 只定义了属性（HP=800），无任何自动攻击逻辑，是个纯占位符。

## ⚙️ 架构方向（非执行项，供 AI 规划时参考）

新战斗系统建议方向：

```
combat/
├── 伤害类型.gd        # enum { 物理, 魔法, 真实, 穿刺 }
├── 护甲类型.gd        # enum { 无甲, 轻甲, 中甲, 重甲 }
├── 伤害计算.gd        # static func 计算(攻击力, 伤害类型, 目标护甲类型, 目标护甲值) → float
├── 战斗组件.gd        # 可挂载到任何角色/建筑的战斗接口
│   ├── func 受伤(伤害, 伤害类型, 攻击来源)
│   ├── signal 受伤时 / 死亡时
│   └── 伤害数字 + 受击效果
├── 索敌组件.gd        # 可配置搜索策略
│   ├── 搜索最近 / 搜索最弱 / 搜索最危险
│   ├── 获取目标()
│   └── 切换策略(策略)
└── 攻击组件.gd        # 攻击属性 + 执行
    ├── 攻击力 / 攻击范围 / 攻击间隔 / 伤害类型
    ├── func 执行攻击(目标)
    └── signal 攻击命中(目标, 伤害)
```

单位头顶 UI 建议方向：
```
ui/单位状态条.tscn     # Control 子场景，挂载到单位/建筑头顶
├── HBoxContainer
│   ├── HP 条 (TextureProgressBar) — 选中时显示
│   └── MP 条 (TextureProgressBar) — 选中时 & 有魔力才显示
└── 通过 CombatComponent 信号驱动更新
```
