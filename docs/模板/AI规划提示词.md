## 请帮我规划

以下是我对当前代码的判断和需求。请你先分析我的判断是否正确，然后给出实现规划。

### 我的判断

1. **战斗链路能跑通但质量不足**
   - 剑士/弓箭手各自实现了完整的 3 态状态机（IDLE/MOVE/ATTACK），但 80% 代码重复
   - 添加新兵种需要复制粘贴，没有可复用的战斗组件
   - 死亡只是 Tween 动画，没有使用 sprite 美术素材
   - 索敌是简单的"找最近敌人"，没有智能策略

2. **需要伤害类型 + 护甲类型体系**
   - 目前所有伤害是裸数值减法，没有克制/减免
   - 需要设计伤害类型（物理/魔法/真实）和护甲类型（轻甲/中甲/重甲）

3. **需要单位头顶血条/蓝条**
   - 不选中时不显示任何血条
   - 选中时显示 HP 条
   - MP 条仅当该单位有最大魔力值 > 0 时才显示
   - 建筑只显示 HP 条

4. **防御塔是占位符，没有攻击逻辑**

### 代码架构现状

- `代码/unit/UnitBase.gd` — 新单位基类，含有战斗方法（受伤/死亡/索敌），但职责过大
- `单位/剑士/剑士.gd` — 继承 UnitBase，状态机在自身实现
- `单位/弓箭手/弓箭手.gd` — 同上，大部分代码与剑士重复
- `单位/建筑/建筑基类.gd` — 独立继承体系（StaticBody2D），但实现了类似的战斗接口
- `combat/` 目录 — 空的，已有 `代码/攻击/` 旧组件但已废弃
- `血量属性.gd` / `步兵攻击.gd` — 旧组件体系，已被现代单位绕过
- 所有战斗属性目前在单位脚本内以 `@export var` 定义，无统一配置

### 我的具体要求

1. **战斗系统组件化** — 提取可复用的 CombatComponent / TargetingComponent / AttackComponent，让新兵种只需组合+配置
2. **伤害类型 + 护甲类型** — 设计完整的伤害计算链路
3. **头顶血条/蓝条** — 单位状态条 UI，条件性显示，与真实数值挂钩
4. **索敌策略可配置** — 支持不同搜索策略（最近/最弱/高威胁）
5. **死亡使用动画** — 接入 AnimationPlayer 播放精灵动画替代 Tween
6. **防御塔攻击逻辑** — 复用组件实现自动攻击
