# Migration Target Report — Phase 2 单位迁移分析

> 生成日期：2026-07-05
> 目标：选择首个迁移到 MovementSolver 的真实单位

## 一、所有单位类型分析

### A. UnitBase 体系单位（新架构）

这些单位 `extends 单位基类`，已附带 `单元状态机` 子节点，适合 MigrationSolver 迁移。

#### 1. 剑士 — ⭐ 首选试点

| 属性 | 值 |
|------|-----|
| 文件 | `单位/剑士/剑士.gd` |
| 场景 | `单位/剑士/剑士.tscn` |
| 实例数 | 3（场景/平面.tscn: 剑士×1, 剑士2, 剑士3） |
| 移动速度 | 250.0（UnitStats 中最高） |
| 战斗类型 | 近战（melee, 无投射物） |

**复杂度评估**：
- ✅ `_physics_process` 仅调 `super._physics_process(delta)` + flip_h 朝向
- ✅ **零 velocity 写入**（纯 UnitBase 行为）
- ✅ 内置 `单元状态机`，无自定义状态管理
- ✅ 无特殊移动逻辑（不建造、不巡逻、不驻守复杂行为）
- ✅ 场景中有玩家和敌人实例方便测试

**风险评估**：**极低**

#### 2. 弓箭手

| 属性 | 值 |
|------|-----|
| 文件 | `单位/弓箭手/弓箭手.gd` |
| 场景 | `单位/弓箭手/弓箭手.tscn` |
| 实例数 | 4（2 玩家 + 2 敌人） |

**复杂度评估**：

- ✅ 内置 `单元状态机`

**风险评估**：**低**（比剑士多一步 projectile 验证）

#### 3. 农民

| 属性 | 值 |
|------|-----|
| 文件 | `单位/农民/农民.gd` |
| 场景 | `单位/农民/农民.tscn` |
| 实例数 | 1（玩家农民1） |
| 移动速度 | 140.0 |
| 建造类型 | 城堡/房子/防御塔 |

**复杂度评估**：
- ⚠️ 有自己的 `State` enum（IDLE/MOVE/BUILD），与 `单元状态机` 共存
- ⚠️ `_physics_process` 中**直接引用 `运动服务.实例`**：
  - 第 99 行：`运动服务.实例.是否在移动(self)` — 建造到达检测
  - 第 105 行：`运动服务.实例.是否是槽锁定(self)` — 队形动画管理
- ⚠️ 建造使用 `移动请求.技能驱动()` + `应用移动请求()` — 不走状态机路径
- ⚠️ 建造有复杂瞬移/残影/计时器逻辑

**风险评估**：**高**（依赖运动服务实例的多个接口，迁移需要额外适配）

### B. 遗留单位（混合系统）

#### 4. 人族步兵 | 5. 人族农民

| 属性 | 值 |
|------|-----|
| 文件 | `代码/兵种/人族步兵.gd`, `代码/兵种/人族农民.gd` |
| 场景 | `卡牌UI/主UI.tscn`（卡牌系统使用） |
| 实例数 | 卡牌系统中 |
| 移动速度 | 100 / 140 |

**复杂度评估**：
- ❌ **直接写 velocity**（`velocity = 移动控制器.compute_velocity(...)`）
- ❌ 使用旧 `UnitController` 替代 `单元状态机`
- ❌ 与 `运动服务` 的流场/卡死检测耦合
- 需要完全重写为 UnitBase 子类后才可迁移

**风险评估**：**不可迁移**（需先做代码迁移到 UnitBase 架构）

## 二、首选迁移对象：剑士

### 选择理由

```
剑士 vs 弓箭手 vs 农民 vs 遗留单位 vs 独立实体

复杂度：    ⭐⭐⭐     ⭐⭐⭐⭐     ⭐⭐⭐⭐⭐    ❌       ❌
velocity干涉： 无        无        有(运动服务引用)  直接写    直接写
状态机：    单元状态机  单元状态机  双重状态机        旧State   无
特殊逻辑：  无        投射物     建造/瞬移          旧UnitCtl 独立
场景实例：  3         4         1                卡牌      独立
```

### 剑士的迁移优势

1. **最简单验证路径**：右键移动 → MovementIntent → MovementSolver → velocity → move_and_slide
2. **零副作用**：无 velocity 写入、无运动服务直接引用、无额外状态管理
3. **场景中有实例**：游戏启动即有剑士，可立即验证移动/攻击/追击
4. **近战单位**：无需验证投射物动画时序
5. **速度最快**：250 px/s，移动行为肉眼可见
6. **敌人+玩家同时存在**：可验证追击行为

### 验证计划

| 测试 | 方法 | 期望 |
|------|------|------|
| MoveTo | 选取剑士，右键地面 | 移动到目标位置，平滑停止 |
| 队形移动 | 多选剑士，右键地面 | 方阵展开，SLOT_LOCKED |
| 攻击移动 | A + 右键 | 移动到目标，沿途遇敌攻击 |
| 追击 | 右键敌人 | 追到攻击范围内停 |
| 攻击 | 进入攻击范围 | 播放攻击动画 |
| 卡死恢复 | 用障碍物阻挡 | 卡死检测→回退→继续移动 |
| 阵营切换 | 敌人剑士 | 同样正常工作 |
