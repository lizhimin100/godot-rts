## 一、当前 MovementSolver 内部的方向来源

MovementSolver 的 `_解析单位()` 方法（L164-306）包含以下方向来源：

### 1. 路径力（PATH FORCE）

| 属性 | 值 |
|------|-----|
| 位置 | movementSolver.gd:246-247 |
| 代码 | `var 路径速度 = data.策略.计算速度(unit, 请求)` |
| 内部 | 策略（前往位置移动） → 流场管理器.获取方向() |
| 方向单位 | px/s（含速度倍率） |
| 输入 | unit.global_position, intent.target_position, formation_offset |
| 权重 | 1.0（不做衰减） |
| 状态依赖 | 无 |
| 迁移状态 | ⏳ **本阶段目标** |

**内部调用链：**
```
策略.计算速度()
  → 获取流场目标()  → 队形系统.获取组目标() 或 intent.target_position
  → 流场管理器.获取方向(pos, target)
  → 刹车/展开逻辑
  → 返回 方向 * 移动速度 * 速度倍率
```

### 4. SLOT_LOCKED 锚点回归力（ANCHOR RETURN）

| 属性 | 值 |
|------|-----|
| 位置 | MovementSolver.gd:197-210 |

### 5. 卡死恢复力（STUCK RECOVERY）

| 属性 | 值 |

## 二、力的优先级层次（由高到低）

```
1. SLOT_LOCKED 锚点回归    ← 最早 return，完全独立
2. 已到达零力              ← 次早 return，velocity=0
3. 卡死恢复力              ← 覆盖三力合成结果
4. 三力合成：
   ├─ 路径力 ×1.0
   ├─ 队形力 ×0.6
   └─ 分离力 ×0.4
```

---

## 三、力融合规则

当前三力合成公式：

```
最终速度 = 路径速度 + 队形力 × 0.6 + 分离力 × 0.4
```

然后：

```
if 最终速度 > 最大速度:
    最终速度 = 最终速度.normalized() × 最大速度
```

**核心问题**：
- 权重与优先级混合（队形力×0.6、分离力×0.4 是权重，但 SLOT_LOCKED 是优先级）
- 权重的物理含义不明确（为什么 0.6/0.4？是经验参数）
- 未来新增力时，权重总和必须手动维护

## 四、与旧运动服务的差异

运动服务（旧）的力来源完全一致（L237-259 三力合成 + 卡死 + SLOT_LOCKED），因为 MovementSolver 是逐字复制。

| 力来源 | 运动服务 | MovementSolver |
|--------|----------|----------------|
| 路径力 | `策略.计算速度()` | 同左 |
| 队形力 | `队形系统.计算队形力()` ×0.6 | 同左 |
| 分离力 | `避障系统.计算让路修正()` ×0.4 | 同左 |
| SLOT_LOCKED | 运动服务 L180-194 | 同左 |
| 卡死 | 运动服务 L281-318 | 同左 |

## 五、Provider 化可行性评估

| 力 | 独立程度 | 对其他力的依赖 | 提取难度 | 建议 |
|---|---------|--------------|---------|------|
| 路径力/流场 | 高（仅依赖 intent.target） | 无 | ⭐ 低 | **本阶段迁移** |
| 队形力 | 中（依赖 slot_state） | 需要 slot_state 标记 | ⭐⭐ 中 | 下一批 |
| 分离力 | 高 | 需要路径方向作为 hint | ⭐⭐ 中 | 下一批 |
| SLOT_LOCKED | 高（完全独立） | 无 | ⭐ 低 | 可与队形力同时 |
| 卡死恢复 | 低（依赖最终速度判定） | 需要 velocity 快照 | ⭐⭐⭐ 高 | 最后迁移 |
